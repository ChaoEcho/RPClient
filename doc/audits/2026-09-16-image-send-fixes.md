## 修复内容

| 问题 | 实现 | 行为边界 |
| --- | --- | --- |
| A：正文与附件快照错配 | `ChatPromptHistoryContext.messages` 仅保存一份 `MessageWithImages` 聚合列表；`GroupChatPromptData` 携带事务内读取的附件快照；两个 ViewModel 使用返回快照准备图片 | 普通发送、重试、续写、重生成共用的构建路径均消费同一图文快照；单聊回退摘要分支也返回图文聚合 |
| B：丢失归属的选图回调 | 协调器用可空 `PendingPick` 登记一次选择，并在成功、失败或取消结果到达时消费 | 新 ViewModel 和重复结果不会默认追加到新消息草稿；保留原有编辑版本校验和配置重建复用行为，无有效记录时显示现有重新选图提示 |
| C：群聊旧图片无法裁剪 | 将 `triggerUserMessageId` 传入 Builder，仅对明确触发本批次的用户图片附加不可裁剪保护 | 批次内后续角色及失败重试继续保护触发图片；无新输入的新批次、AutoMode 后续批次中的旧图文可以按预算整条裁剪，最新消息仍保留原保护 |
| D：空草稿错误提示隐藏 | 托盘提前返回条件增加“没有错误提示” | 首图准备失败后即使附件为空，也会显示错误与重新添加入口 |
| E：Gemini 请求文件残留 | URL 解析及构建在 `codec.prepare()` 创建请求临时文件前完成 | 非法 URL 不再产生本次请求文件；编码后其他请求构建异常仍由既有 `toHttpRequest` 清理 |
| F：草稿图片排序入口丢失 | 非首张草稿图片支持长按菜单“前移”，发出 `Move(editing = false)` | 复用已有本地化文案；处理或生成期间禁止移动；附件列表或可操作状态变化时关闭菜单 |

图文快照事务只读取数据库，不在事务内执行图片解码或压缩。读取完成后如果原附件被并发删除，仍由现有资源校验报告不可用或按历史预算裁剪，不会改读新附件与旧正文拼接。
