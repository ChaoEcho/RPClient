# 图片存储与编辑流程简化

## 适用范围

- 版本尚未发布，按全新安装处理，不迁移旧记录，也不增加旧缓存清理逻辑。
- 单聊、群聊的新消息发送和历史消息编辑使用同一附件提交流程。

## 最终行为

- 选图只复制到通用仓库的暂存区并校验格式，保留源草稿供预览和失败重试。
- 点击发送或保存编辑时冻结设置，只处理新增图片。最终字节、实际 MIME 和内容哈希由通用仓库统一登记。
- 图片处理在事务外完成；正文、附件关系和文件索引仍在同一事务提交。处理失败或事务回滚时释放本次处理结果，保留原消息和源草稿。
- 提交成功后释放源草稿。历史显示、保存图片、模型请求、摘要和重试直接读取已入库的同一文件。
- 编辑文字、排序及保留已有附件不重新压缩；移除已有附件仅在保存成功后释放引用，取消编辑不影响原记录。
- 删除最后一个文件引用后复用仓库回收机制；分支共享引用和正在进行的读取仍受到保护。
- 移除独立发送图片缓存、缓存版本键、重建和容量淘汰逻辑，以及未使用的旧 UI 包装入口。
- 查看器只保留图片查看、缩放、切换及保存；Prompt 检查器使用“查看图片”入口。
- 图片设置只影响新增附件，相关说明同步更新全部现有语言。

## 验证

- 离线 Debug 构建成功。
- JVM 单元测试：269 项通过。
- Android 模拟器：图片协议及资源集成、仓库生命周期、真实单聊和群聊页面流程共 41 项不同测试通过。
- 关键回归覆盖实际压缩与透明通道、设置冻结、历史字节稳定、导出最终文件、删除回收、多图中途失败、文件生成取消、编辑事务回滚与重试，以及群聊页面新增图片保存和取消编辑。
- 无需调用外部模型服务：页面流程使用模拟器回环地址的合成响应，文件用例使用合成图片及隔离目录。
